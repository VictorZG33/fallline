# Fall Line

A static PWA (no build step) served by GitHub Pages at https://wentaoz.com/fallline/.
See README.md for what it does and where each piece lives.

## Conventions

- Plain ES modules in `js/`, loaded by `index.html`. No bundler, no npm runtime deps.
- Third-party code is vendored and pinned in `vendor/` (MapLibre GL JS 6.13.0,
  maplibre-contour 0.1.1) so the service worker can control MapLibre's worker
  and the app works offline. Upgrade by copying the new `dist/` files over.
- All URLs are relative: the app lives under `/fallline/`, not at the root.
- Interface text goes through `t()` in `js/i18n.js`; add every key in both `en` and `zh`.
- Numbers with units go through `js/format.js` (metric or imperial).
- When you change a file listed in `SHELL_FILES` in `sw.js`, bump `VERSION`.
- `data/` is generated by `tools/build-data.mjs`; don't edit it by hand.

## Testing

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

Then drive it with Playwright (Chromium with `--use-angle=swiftshader` for WebGL).
`window.fallline.map` is the MapLibre map. The map hash (`#zoom/lat/lon/bearing/pitch`)
sets the view, e.g. `#13.4/44.53/-72.79/290/62` for Stowe.

## Terrain engine

`js/terrain.js` is the core: Mapterhorn terrarium tiles (512 px, webp, max zoom
varies by region: 404 above the finest data, so `bestZoom` walks down). Shading
uses Horn's method over a baseline (slope ~12 m, aspect ~40 m plus a box blur),
on the coarsest DEM zoom that still resolves that baseline, then interpolates the
gradient to the output tile. Keep it free of DOM APIs; it runs in
`terrain-worker.js` and, as a fallback, on the main thread.

The winter satellite base map (`snowTile`) is drawn by the same workers from Esri
imagery and the 12 m gradient. Forest is detected in the image; groomed runs and
lift lines come from `setOpen` (sent by `sendOpenGround` in `js/app.js` whenever
the piste data changes) and are always kept clear. Tune it by eye at Stowe, Big
Sky, Jackson Hole and Chamonix: forest types and imagery seasons differ a lot.

Run stats (`analyze` in `js/info.js`) are all measured along the line: average
pitch is drop over length, steepest is the worst 30 m, and the profile is coloured
by that same pitch. `trail()` in `js/pistes.js` joins same-named OSM sections that
continue from each other, so a tap gives the whole signed run.

"Fly down" (`flyAlong` in `js/info.js`) plans the whole flight before it starts:
for keyframes along the line it tries camera placements behind and to the side,
reads DEM heights along each sight line through the worker (`terrain.heights`),
raises the camera until the sight line clears the terrain, and keeps the
placement that looks down least steeply. Check changes against a steep line
such as Big Couloir at Big Sky (`#15/45.2797/-111.4475/0/0`).
